# P2 编程能力优化插件：实现成本与可能性评估

> 评估日期：2026-10-30 | 宿主：dsh 0.2.1-rc.3 | 口径见 `HANDOFF-插件评估.md` §2

## 0. 结论摘要

**「做一个编程能力插件」不成立——这个需求已经分裂成 5 类，且没有一类能靠自研取得优势。**

- 唯一实质提升「写代码」能力的是 **LSP 动作面**（`dsh-lsp-actions`），官方已有 `ctx.lsp` 导航，它补诊断/格式化/补全/代码动作/重命名；成本中等（要装语言服务器），值得按语言按需装。
- **审查类**（`brooks-lint`）与**测试类**（`dsh-qa-skills`）是技能包，成本≈0，收益是流程质量，不改变代码生成能力。
- **工作台**（`dsh-native-code-workbench`，2★、15 天未更新）与**模型编排**（`dsh-model-fusion`）性价比低，暂缓。
- **审批自动化**（`dsh-auto-review`）是「无人值守」能力，不是编程能力，不归 P2。
- **自研否决**：模型能力是主瓶颈；LSP 协议 + 多语言服务器是重工程且已有现成；技能类本质是提示词，自研无壁垒。

**一句话**：P2 的正确形态是「按缺口装现成件」，不是「造一个新插件」。

## 1. 需求边界：「编程能力」拆成五个缺口

| # | 缺口 | 表现 | 能否插件补 |
|---|---|---|---|
| G1 | 反馈闭环 | 写完代码不知道有没有编译/类型错误，只能跑命令或再读一遍 | 能（LSP 诊断） |
| G2 | 质量门禁 | 改完没人审，问题留到运行期 | 能（审查技能 / 第二模型） |
| G3 | 测试流程 | 用例设计、回归范围靠经验 | 能（测试技能） |
| G4 | 编辑体验 | 没有语法高亮、补全、跳转 | 能（工作台 / 编辑器协议） |
| G5 | 模型编排 | 单模型能力上限 | 能（多模型分工） |

不解决：模型本身的推理/代码生成能力（插件改不了）；上下文窗口与成本（属 compaction/模型选择）。

## 2. DSH 当前能力基线（已有什么）

- 文件：`read` / `write` / `edit` / `insert` / `undo_last_edit`（编码已由 P1 插件治理）
- 检索：`glob` / `grep`（ripgrep）
- 执行：`bash` / `pwsh` 持久 shell、后台 job
- 编排：`subagent` / `subagent_fork` / `workflow`、plan mode、compaction
- 协作：任务列表、`present`、`web_search` / `web_fetch`
- 缺的正是 **G1 反馈闭环** 与 **G2 门禁**：没有 LSP 诊断、没有语义索引、没有内置测试运行器/审查器。

## 3. 候选逐一评估

### 3.1 LSP 动作面：`dsh-lsp-actions` 0.5.17（34★，PerryLink，Apache-2.0）

- **形态**：纯 host 插件，`inject: [tools, fs, subprocess]`，挂一行 `id: lsp-actions`；注册 8 个 `lsp_*` 工具（诊断、格式化、补全、代码动作、符号、签名提示、内联提示、重命名）。
- **与官方的关系**：官方 `ctx.lsp` seam 已覆盖**导航**（跳转定义/引用/实现/悬停），本插件补的是**动作面**——agent 改代码时需要的反馈闭环。
- **不调用模型**，靠真实语言服务器（typescript-language-server 已随测试套件实测；其他语言需各自 server）。
- **兼容**：`engines.dsh: >=0.2.1-0 <0.3.0`，当前 0.2.1-rc.3 命中。
- **成本**：装插件 0.5 天；每个语言装/配 server（TS/JS 一条命令，Python `pyright`，Go `gopls`，Rust `rust-analyzer`）0.5–1 天/语言；每语言 server 常驻内存（几十 MB）。
- **收益**：G1 从「跑命令才发现」变成「改完立即诊断」；重构（rename/代码动作）有服务器背书，误改率下降。
- **风险**：server 版本与项目 toolchain 不匹配；多语言 = 多进程管理；插件自建 LSP 客户端，宿主升级可能改 seam。
- **结论**：**唯一推荐装的一类**，但按语言装、不要一次全上。

### 3.2 审查技能：`brooks-lint` 1.9.1（1544★，MIT）

- **形态**：可移植 Agent Skills（`skills/` 目录 + `bin/` + `cordis.patch.yml`），六个命令 `/brooks-review`、`/brooks-audit`、`/brooks-debt`、`/brooks-test`、`/brooks-health`、`/brooks-sweep`；输出「症状→根源→后果→对策」+ 0–100 健康分。
- **本质**：提示词 + 参考知识库，不是工具增强；不会自动跑，靠模型/用户触发。
- **成本**：0.5 小时装 + 每次审查的 token（读代码 + 输出诊断）。
- **收益**：G2 的「深度」提升（十二本书的方法论、分级、可溯源）；适合 PR 前自检。
- **风险**：技能触发靠自觉；审查结论仍是模型判断，不替代测试；1544★ 但非 DSH 专属，DSH 适配层薄。
- **结论**：**低成本可选**，装了不亏，别指望它提升生成能力。

### 3.3 测试技能：`dsh-qa-skills` 0.6.0（54★，MIT）

- **形态**：纯技能包（10 个测试技能 + 共享知识库），`.dsh/plugins/qa-skills.js` 注册。
- **成本**：≈0；收益：测试策略/用例/回归范围的知识注入。
- **结论**：可选；与 brooks-lint 的 `/brooks-test` 有重叠，二选一即可。

### 3.4 代码工作台：`dsh-native-code-workbench`（2★，15 天未更新）

- 形态：右栏 Monaco + FIM Tab 补全 + `codebase_search` + 检查点回滚。
- 问题：与 DSH 自身对话/编辑流程重叠；星标极低、明显停更；npm 上包名 `dsh-native-code-workbench` 已 404（实际装名 `dsh-code-workbench`），供应链信息混乱。
- **结论：否决**（性价比与维护风险都不过关）。

### 3.5 模型编排：`dsh-model-fusion` 0.2.9（69★）

- 形态：Lead 规划审查 + Sidekick 执行的双模型线路。
- 成本：每次任务至少 2 倍调用/延迟；收益：不确定，取决于分工质量。
- **结论：暂缓**（先解决 G1/G2，编排是最后一步）。

### 3.6 审批自动化：`dsh-auto-review` 0.15.0（234★）

- 本质：审批链上的第二模型（或 150M 本地模型）自动 allow/deny，fail-closed。
- 这是「无人值守」能力，不是编程能力；每审批一次多一次调用。
- **结论：不归 P2**，若以后要长时间无人值守再评。

## 4. 性价比矩阵

| 缺口 | 候选 | 成本 | 收益确定性 | 性价比 |
|---|---|---|---|---|
| G1 反馈闭环 | dsh-lsp-actions | 中（0.5 天 + 每语言 0.5–1 天） | 高（诊断可量化） | **高** |
| G2 质量门禁 | brooks-lint | 低（0.5 小时） | 中（依赖触发） | 中高 |
| G3 测试流程 | qa-skills | 极低 | 中低 | 中 |
| G4 编辑体验 | workbench | 中 | 低（重叠+停更） | **低** |
| G5 模型编排 | model-fusion | 高（2x 调用） | 低 | **低** |
| — | 自研编程插件 | 很高（LSP 协议+多语言） | 低（已有现成） | **否决** |

## 5. 结论

1. **P2 不立项自研。** 所谓「编程能力插件」没有单一形态，自研无法覆盖；LSP 这类硬能力已有成熟实现，技能类没有技术壁垒。
2. **按缺口装现成件**：
   - 若你主要写 TS/JS/Python → 装 `dsh-lsp-actions` + 对应语言 server，这是唯一能实质改变「写完立即知道对错」的增强。
   - 想要审查深度 → 装 `brooks-lint`（低成本）。
   - 工作台、模型编排、审批自动化 → 暂不装。
3. **先量化再决定**：装 LSP 前记录一周内「编译/类型错误平均多久发现」，装后再记一周；没有改善就卸掉。
4. **风险总账**：多语言 LSP = 多进程 + 版本匹配；技能类 = token 成本与触发不确定性；两者都不改模型能力本身。

## 6. 建议动作（若用户确认）

1. 先只装 `dsh-lsp-actions`，配 1 个语言（TS/JS 或 Python），用一周；
2. 量化 G1 指标（诊断首次命中时间、返工轮数）；
3. 有效再扩语言；无效直接卸（`dsh plugin remove`）；
4. `brooks-lint` 作为 PR 前自检技能，与 LSP 并行不冲突。
