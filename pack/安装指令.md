# 重修整合包 v2 · 安装指令（给 DSH agent 的 SOP）

> 用户会发：「按 `<这个文件>\安装指令.md` 安装重修整合包」。
> 你在一台已装 DSH 的 Windows 机器上工作。**核心规则：每一个安装项都必须单独出一张 `ask_user_question` 卡片，用户确认或修改后才装。**
> 不许一次性问「全装吗」，不许跳过卡片直接跑脚本。

## 0. 定位包目录

本文件所在目录就是包根目录，里面应有 `install.ps1`、`payload\`、`SHA256SUMS.txt`。
后续命令里的 `<包>` 一律替换成该目录的**绝对路径**（路径含中文和空格，命令里必须加引号）。

## 1. 预检（10 秒，不出卡片）

- `$env:USERPROFILE\.dsh\profiles` 存在 → 不存在就停，告诉用户「需要先安装 DSH 并启动一次」。
- `<包>\payload\plugins\dsh-task-list\package.json` 存在 → 不存在说明包不完整，停。

## 2. 逐项确认（7 张卡片，一张一张出，等回答再出下一张）

每张卡片的固定结构：**这项装了什么 / 不装的后果 / 会改动什么**。用户可以在回答里说「改主意」「只装一半」「改配置」，你按他的说法调整最终列表。

### 卡片 1 · 工作区美化

- 问题：`要装「工作区美化」吗？侧栏改成 工作区 → 分组 → 会话，支持拖拽归类、上下文用量环、20%/40% 上下文提醒。`
- 选项：
  1. `装（推荐）`
  2. `不装`
  3. `装，但我先看看说明`（你贴 README 对应段落，再问一次）

### 卡片 2 · 任务列表

- 问题：`要装「任务列表」v0.3.8 吗？对话左侧常驻任务面板（四态 + 完成区 + 废弃区 + 父子折叠）。注意：它会禁用宿主自带的 todo_write，并把上下文压缩阈值从 0.8 降到 0.4。`
- 选项：
  1. `装（推荐）`
  2. `不装`
  3. `装，但保留宿主 todo_write`（你需要在装完后手动把 `preset-standard` 补丁段里的 `tool-todo` 改回启用——先告知用户这一步是手工的）

### 卡片 3 · 编码插件

- 问题：`要装「编码插件」吗？让 read / write / edit 自动识别 GBK、UTF-16、Big5 等编码，不再报 E_NOT_TEXT。`
- 选项：`装（推荐）` / `不装`

### 卡片 4 · LSP + 代码审查

- 问题：`要装「LSP 诊断 + 代码审查」吗？会把 lsp_diagnostics / lsp_symbols 打开（TypeScript/JavaScript），并装上 brooks 系列审查技能。会额外装 typescript 5.9.3 和 TS 语言服务器（需要联网解析依赖）。`
- 选项：
  1. `装（推荐）`
  2. `不装`
  3. `只装审查技能，不要 LSP`（那就只装 brooks-lint：在最终命令里去掉 lsp 项，单独告知用户审查技能怎么装）

### 卡片 5 · 视觉（识图/截图）

- 问题：`要装「视觉」吗？提供 analyze_image 识图和 screenshot 截屏。注意：识图需要你自己在 ~/.dsh/vision.env 里配 API Key（包里不带 Key）。`
- 选项：
  1. `装（推荐）`
  2. `不装`
  3. `装，但我没有 Key`（装完提醒他配，不影响其它模块）

### 卡片 6 · 皮肤

- 问题：`要装皮肤 dsh-claude-style 吗？会改界面配色、圆角、背景，本机用的就是它；不装不影响任何功能。`
- 选项：
  1. `装（推荐，本机同款）`
  2. `不装`

### 卡片 7 · 白皮书（先对比再问）

先做对比，把事实写进卡片：

1. 读 `<包>\payload\AGENTS.md`：行数 + 章节标题列表（`## 第X条 ...`）。
2. 读 `$env:USERPROFILE\.dsh\AGENTS.md`（存在才读）：行数 + 标题列表。
3. 算差异：新版有、旧文件没有的章节 = 「新增」；旧文件有、新版没有的 = 「本地独有」。

- 问题示例：`白皮书（~/.dsh/AGENTS.md）怎么处理？目标机现有 X 行，新版 Y 行；新增章节：…；本地独有：…`
- 选项：
  1. `覆盖，先自动备份旧文件（推荐）`
  2. `只补新版有、旧文件没有的章节（保留本地增补）`
  3. `不动`

## 3. 汇总执行（一条命令）

把用户确认的项拼成逗号列表（不装的项不要写进去）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<包>\install.ps1" -Include "<workspace,tasklist,encoding,lsp,vision,skin>" -AgentsPolicy "<overwrite|append|keep>"
```

- 没装皮肤 → `Include` 里不要有 `skin`。
- 白皮书选了「不动」→ `Include` 里不要有 `agents`，`AgentsPolicy` 用 `keep`。
- 用户可以随时改主意：重跑一条命令、换 `Include` 即可（幂等，不会重复追加配置）。

成功标志：

```
本次安装项目: workspace, tasklist, encoding, lsp, vision
   [ok] 选中项目的依赖 / bundles / node_modules 全部就位
安装完成。
```

失败时：**原样**把错误贴给用户，指向 `README-安装说明.md` §八，不要自创方案。

## 4. 让用户重启

明确告诉用户：

> 全部装好了。请**完全退出 DSH**（托盘图标也要退出，不只是关窗口），重新启动，然后刷新页面。

不要尝试自己重启宿主进程；只刷新页面插件不会生效。

## 5. 安装后自检（重启成功后做）

1. 读 `<profile>\package.json`，确认 `dsh.profile.bundles` 含本次所有选中项。
2. 装了 LSP → 对任意 `.ts` 调 `lsp_diagnostics`；报 `LSP_ACTION_SERVER_FAILED` 就检查 typescript 是不是 5.9.x。
3. 把 `README-安装说明.md` §五 的验证清单发给用户，让他按清单自查界面。

## 6. 失败处理速查

| 报错 | 处理 |
|---|---|
| 未找到可用 profile | 让用户先启动一次 DSH |
| 未找到 runtime node/pnpm | DSH 安装不完整，重装 DSH |
| `pnpm add` 非 0 退出 | 需要联网：检查网络/代理/registry 后重跑（包内已带插件 tgz，不会下载插件本体） |
| 校验缺项 | 把缺项清单贴给用户，附备份目录路径，建议按 README §七 回滚后重试 |

## 7. 硬性约束

- 每个安装项必须单独一张卡片，卡片里必须写清「装了什么 / 不装后果 / 改动了什么」。
- 不改包里任何文件；不手工往 `node_modules` 复制东西。
- 命令一律用绝对路径，`-File` 后必须带引号。
- 白皮书只按用户在卡片里的选择处理，不默认覆盖。
- 用户说「全都装」「按推荐来」可以一次确认，但你仍要先把 7 项汇总成一张清单给他确认，再执行。
